# UI 改版设计文档

本文档记录 v0.2.0-dev 界面改版的设计决策与实施范围。
目标是把界面从 Compose 模板默认样式改为有明确设计意图的现代形态。

---

## 1. 现状问题

改版前的实际状态（v0.1.4-dev）：

| 问题 | 位置 | 说明 |
| --- | --- | --- |
| 配色未设计 | `ui/theme/Color.kt` | 仍是 Compose 模板生成的 `Purple80` / `Purple40` 一套，品牌色 `#FCA43C` 只存在于应用图标，从未进入界面 |
| 动态取色掩盖了缺失 | `ui/theme/Theme.kt` | `dynamicColor = true`，Android 12+ 完全跟随壁纸，因此"没有设计"这件事不易察觉；Android 12 以下则落回模板紫色 |
| 阴影建立层次 | `ui/home/HomeScreen.kt` | `Card` + `elevation = 2.dp` 是 Material 2 语言，投影是"老式感"的主要来源 |
| 排版未定义 | `ui/theme/Type.kt` | 仅覆盖 `bodyLarge` / `titleLarge` / `labelSmall` 三项，其余全为默认 |
| 信息密度平均 | 首页列表 | 每项等大等距同样式，视觉无落点 |
| 顶栏浪费 | 首页 / 聊天页 | 显示应用名 "AfyzHub"，用户不需要在应用内被告知应用名称 |

结论：不是设计得普通，而是尚未设计。改版是补齐，不是推翻。

---

## 2. 设计方向

参考对象为 RikkaHub（<https://rikka-ai.com/>）。它验证了一条可行路径：
**保留 Material You 动态取色，靠 tonal surface 色阶、结构设计与细节做出品质，而非固定品牌配色。**

采纳其结构与视觉系统，在信息呈现方式上做差异化。

### 2.1 差异化定位

RikkaHub 把请求信息（token 用量、缓存命中、吐字速度、耗时）全部常驻显示在每条消息下方，
配合完整时间戳与操作按钮行，一条消息附带三行元信息。信息全面，但默认状态偏拥挤，且无主次。

本项目的处理方式：**信息同样完整，但由用户决定暴露程度。**

在设置中提供一组独立开关，分别控制时间戳、token 用量、生成速度、耗时、操作按钮行的显示。
默认只开启时间戳与操作行，其余关闭。重度用户可全部打开获得完整调试视图，
轻度用户保持界面安静。选择权交给用户，而不是由应用替其决定。

### 2.2 明确不做

以下为参考对象的功能护城河，工程量大且不属于界面改版范围：

- Agent 工作区（proot Linux 环境）— 体积代价数十 MB，且与聊天客户端定位不符
- MCP 支持
- Web 界面
- 搜索增强（Exa / Tavily / Brave）
- 消息分支 — 需将消息表由线性改为树形，属数据层重构
- LaTeX / Mermaid 渲染 — 需引入渲染引擎或内嵌 WebView
- 追问建议 — 实际使用频率低，暂不实现

## 3. 视觉系统

### 3.1 配色

保留 `dynamicColor`。同时为 Android 12 以下设备提供一套以品牌色 `#FCA43C` 为种子色生成的
完整 M3 色板，使旧设备也有确定的视觉效果，且品牌色得以呈现。深色模式手动调校，
不依赖 `darkColorScheme` 自动推导；深色背景不使用纯黑，采用带色相倾向的深灰。

**层次一律由 tonal surface 色阶建立，`elevation` 保持 0。禁用阴影与描边。**

颜色角色分配：

| 用途 | 颜色角色 |
| --- | --- |
| 页面背景 | `surfaceContainer` |
| 消息块（助手） | `surfaceContainerLow` |
| 消息块（用户） | `primaryContainer` |
| 输入区容器 | `surfaceContainerHigh` |
| 抽屉选中项 | `secondaryContainer` |
| 日期分组标题 | `primary` |
| 次要文字 / 元信息 | `onSurfaceVariant` |

强调色仅用于日期分组标题与激活状态，不做大面积铺色。

### 3.2 形状

统一到大圆角语言：

- 输入区容器 28dp
- 消息块 20dp（用户消息可将靠身侧一角改为 4dp 以指示方向）
- chip / 选中态 全圆角胶囊
- 发送按钮 正圆
- 抽屉右侧上下角圆角，宽度不占满屏幕

### 3.3 排版

补全 `Typography` 全部样式档位。

引入外部字体，拉丁字形使用 Inter（几何感 sans，UI 场景可读性优于系统默认）。
实现方式为 **Google Fonts downloadable fonts**（`androidx.compose.ui:ui-text-google-fonts`）：
字体文件由系统字体提供方按需下载并跨应用共享，**打包体积增加为零**。
中文字符 Inter 不覆盖，自动回落系统中文字体，因此不需要处理中文子集化。
字体提供方不可用（无 Play 服务、下载失败）时降级为 `FontFamily.Default`，不影响可用性。

代价是首次显示可能有短暂字体切换。体积上限已定为正式版 100MB 以内，
若后续需要完全离线保证，可改为打包 Inter 子集（约 200KB 量级），届时再评估。

动效同样承担"现代感"：M3 shape morph、列表项进场、流式文字渐显。

体积基线：正式版 1.0.0 控制在 100MB 以内。当前 3MB，界面改版阶段的增量可忽略。

## 4. 页面结构

### 4.1 导航变更

移除独立首页。抽屉承载对话列表，聊天页作为启动目标。

```
改版前：Home（对话列表）→ Chat → Settings
改版后：Chat（根，含 ModalNavigationDrawer）→ Settings
```

`HomeScreen` 溶解为抽屉内容，`HomeViewModel` 保留（对话列表逻辑不变）。
`NavGraph` 目的地由三个减为两个。

取舍：省掉一次跳转，打开应用即可输入，契合 AI 客户端"打开就说话"的使用模式。
代价是失去总览视角，对话量大时抽屉内翻找成本上升，后续由分组与搜索功能缓解。

### 4.2 抽屉

- 对话列表按时间分组，粘性标题（今天 / 昨天 / 更早），标题用强调色
- 列表项为标题 + 一行摘要（末条消息截断）。参考对象仅显示标题，
  导致相邻的相似会话无法区分，故增加摘要
- 项内不放删除按钮，删除走长按菜单
- 底部仅保留两行，均带文字标签：
  - 当前助手（图标 + 名称，点击切换）
  - 设置（齿轮 + "设置"）

参考对象底部为五个无文字标签的圆形图标按钮，可发现性差，不予采纳。

### 4.3 聊天页

**顶栏**：主标题为会话名，副标题为 `助手名 / 模型名 (提供商)`，两者均可点击。
空会话时隐藏会话名，仅显示助手与模型，避免与首屏问候语重复。

**空会话首屏**：

- 问候语置于屏幕垂直方向约 40% 处（非正中，正中显空）
- 内容按时段变化：早上好 / 下午好 / 晚上好
- 字号 `headlineSmall` 量级，过大会显出营销页感
- 下方留白后放 3–4 个提示词 chip，横向可滑动
- chip 内容为**用户自行配置的常用提示词**，非 AI 生成。生成建议需额外请求，
  耗时耗 token，且新会话时模型缺乏上下文，产出质量低
- 首次安装提供默认值，设置页内可修改
- 此屏不放其他内容。留白本身在暗示"等待输入"

**消息块**：

- 弃用左右气泡布局，助手消息全宽，使代码块与表格获得完整宽度
- 助手消息头部显示模型图标与模型名，便于识别单会话内切换过模型的情况
- 元信息（时间戳、token、速度、耗时、操作行）按设置开关决定是否显示
- 同日消息时间戳仅显示 `HH:mm`，跨日才带日期

**输入区**：整体为单一容器，上半为输入框，下半为功能图标行。
功能行左起：当前提供商标识、联网搜索、思考模式（激活时着色）、附件（+）、发送。
将"本条消息以何配置发出"暴露在拇指可达处，优于藏入设置页。

### 4.4 设置页

现为 256 行单页平铺，改为**两级结构**：一级页面只做分类导航，具体项在子页面内。
参考对象采用同一模式，一级页承载十余个入口仍然清晰。

#### 一级页面版式

- 页面标题「设置」独立成行，大字号（`headlineLarge` 量级），不使用标准 `TopAppBar` 标题栏
- 返回键为左上角圆形按钮，浮于内容之上
- **分类标题置于容器外部**，用强调色（`primary`），字号 `labelLarge`
- 同类入口装入一个圆角容器（`surfaceContainerLowest`），项间靠间距分隔，**不使用分割线**
- 每个入口为：图标 + 标题 + 副标题。副标题说明该项管什么，使一级页面能承载较多入口而不晦涩
- 仅取值简单、无需展开的项直接在行内放控件（如颜色模式的下拉），不跳转子页

#### 分类与入口

当前阶段只做必要项，不铺开到参考对象的规模。

| 分类 | 入口 | 形式 | 内容 |
| --- | --- | --- | --- |
| 通用 | 颜色模式 | 行内下拉 | 跟随系统 / 浅色 / 深色 |
| 通用 | 外观 | 子页面 | 动态取色开关，后续放主题相关项 |
| 模型与服务 | 提供商 | 子页面 | 提供商横向可视化选择（不用下拉，每家配标识）、API Key、地址、模型选择与列表获取 |
| 模型与服务 | 默认模型与提示词 | 子页面 | 首屏提示词 chip 配置，后续放系统提示词 / 助手 |
| 对话 | 消息显示 | 子页面 | 元信息开关组（时间戳 / token 用量 / 生成速度 / 耗时 / 操作行） |
| 对话 | 流式输出 | 行内开关 | 现有 `streamEnabled` |
| 关于 | 关于 | 子页面 | 版本号、仓库链接、更新日志链接 |
| 关于 | 请求日志 | 子页面 | HTTP 请求记录，见下 |

#### 请求日志

参考对象将其放在「关于」分类下作为次要功能。本项目将其作为透明化定位的载体做完整：
记录每次请求的时间、提供商、模型、状态码、耗时、token 用量，可展开查看实际请求体与响应体。

注意**请求头中的 API Key 必须脱敏**，日志仅保留在本机，容量设上限并支持清空。

此项独立于界面改版，排在数据层改动（第 5 节）之后。

## 5. 数据层前置改动

以下 UI 项依赖数据层变更，需先完成：

### 5.1 MessageEntity 加列（Room 迁移）

当前字段：`id` / `conversationId` / `content` / `role` / `status` / `errorMessage` / `createdAt`。
缺少模型标识与用量数据，需新增：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `model` | `String?` | 生成该消息的模型名，用于消息头标识 |
| `promptTokens` | `Int?` | 输入 token 数 |
| `completionTokens` | `Int?` | 输出 token 数 |
| `latencyMs` | `Long?` | 生成耗时 |

均可空，历史消息为 null 时 UI 不显示对应元信息。
需要提供 Room 迁移，不可破坏性重建——已安装设备的对话数据必须保留。

用量数据来源：非流式响应取 `usage` 字段；流式需在最后一个 chunk 中读取
（OpenAI 需请求时带 `stream_options.include_usage`，Claude 在 `message_delta` 事件中给出，
Gemini 在 `usageMetadata` 中给出）。三家格式不同，需在各 `ChatClient` 内分别解析。

### 5.2 AppSettings 扩展

当前 5 个字段：`provider` / `apiKey` / `model` / `baseUrl` / `streamEnabled`。
新增元信息开关与外观项，遵循现有按提供商隔离的存储方式（这些为全局项，不需按提供商分开）。

## 6. 实施拆分

| 阶段 | 内容 | 风险 |
| --- | --- | --- |
| 1 | 主题层重写：`Color.kt` / `Theme.kt` / `Type.kt`，M3 色板、tonal 层次、深色配色 | 低，纯样式 |
| 2 | 导航重构：抽屉替代首页，`NavGraph` 调整 | 中，涉及导航与状态提升 |
| 3 | 聊天页重做：消息块、输入区、顶栏、空会话首屏 | 中 |
| 4 | 抽屉内容：时间分组、摘要、底部两行 | 低 |
| 5 | 设置页两级化：一级导航页 + 各子页面，含元信息开关组 | 中，页面数量增加 |
| 6 | Room 迁移 + 三家 usage 解析 + 元信息渲染 | 中，需迁移测试 |
| 7 | 请求日志页（含 API Key 脱敏、容量上限、清空） | 中 |

阶段 1–5 为纯 UI 层，不触碰 data / domain。阶段 6、7 可独立于界面改版发布。

## 7. 版本安排

改版发布为 **v0.2.0-dev**。取次版本号而非 `0.1.5`，因其为用户可直接感知的变更。
`versionCode` 继续递增（当前 6，下一个为 7），不可回退，否则已安装设备无法覆盖升级。

后续功能在界面规范确立后依次加入：系统提示词 / 助手体系、对话管理（分组、搜索、导出）、
图片上传（三家多模态请求体格式各异：OpenAI `image_url`、Claude `source.base64`、
Gemini `inlineData`，工作量高于表面预期，排后）。
